The original booking exercise could admit overlapping stays for different guests and accepted persistence entities and client ownership assumptions. This change turns the same repository into **NoirStay**: a Java 21/Spring Boot 4.1.2/PostgreSQL application with an original Next.js interface, 24 fictional South African stays and isolated guest, host and administrator journeys.

Reservations share a PostgreSQL inventory exclusion constraint, ten-minute holds, explicit transactional expiry and persisted idempotency responses. Simulated payment/confirmation and cancellation/refund/inventory release commit atomically. Agreed prices and policies are snapshotted, identity derives from HttpOnly Spring sessions, and CSRF protects mutations. Normal startup has no demo access or privileged fixtures.

Guest search, galleries, availability, registration/login, wishlists, checkout, persisted trips, cancellation and reviews work through Spring. Hosts manage drafts, photographs and calendars; administrators review publication and audit records within their visitor's context. Docker Compose, CI, OpenAPI, deployment/rollback guidance, case study and real screenshots are included.

Validation: **30 backend tests**, including real PostgreSQL/Testcontainers concurrency and ownership tests; **5 frontend unit tests**; lint and strict TypeScript checks; backend jar and Next production builds; **9 desktop/phone browser checks**, with axe and 21 passing contrast measurements. The same authenticated confirmed reservation survives a backend container restart. Exact evidence and limitations are in [docs/VERIFICATION.md](https://github.com/danmjrn/noirstay/blob/feat/noirstay-portfolio/docs/VERIFICATION.md).

The existing repository was renamed in place to `danmjrn/noirstay`, preserving main/history/ownership. Description and all eight topics were verified, and milestones were pushed over SSH. This PR leaves main unchanged for review.

Deliberate scope: one independently reservable unit per listing, flat nightly rates, ZAR, local persistent media and simulated payments/email. No MySQL data migration or production capacity is claimed. No authorized public deployment target was supplied; the tested preview is local. Previously committed credential categories requiring rotation are documented without values. No history rewrite, force push or merge is performed.
